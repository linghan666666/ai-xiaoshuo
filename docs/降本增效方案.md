# AI 小说写作平台 · 降本增效方案（v1）

> 目标：**操作更简单、流程更短、成本更低、质量不降反升**，且每一项都可验证、可回滚。
> 适用范围：长篇（long_novel）、完本中篇（mid_novel）、短篇（short_story）、番茄短故事（fanqie_short）全流程。

---

## 一、现状诊断

### 1.1 结构

| 项 | 现状 |
|---|---|
| 流程 | 4 条：长篇 9 步 / 中篇 10 步 / 短篇 8 步 / 短故事 8 步 |
| 页面 | 7 个：知识库、写作流程、章节、封面、违禁词、模型、短故事 |
| 每章默认模型调用 | 3–5 次：起草、改写、摘要、伏笔、（逻辑扫描） |
| 上下文注入 | 最近 6 章摘要 + 上一章结尾 600 字 + 3 个 skill 原文块 |

### 1.2 成本结构（按调用次数估）

| 环节 | 占比 | 说明 |
|---|---|---|
| 起草 | ~30% | 每章 1 次，输入最大（设定/大纲/前情全量注入） |
| 改写（去 AI 味） | ~45% | 每章 1 次，原文 + 输出都计费 |
| 摘要 + 伏笔 | ~20% | 每章 2 次 |
| 逻辑扫描 | ~5% | 每章或抽样 |

### 1.3 问题清单（均为实测）

| 类别 | 问题 |
|---|---|
| 操作 | 建书要填 6 项；跑一篇要点 10+ 次；短故事页与写作流程页重复 |
| 流程 | 章节级步骤无法批量；已完成的步骤不会自动跳过 |
| 成本 | 未设全局默认模型 → 回退到最贵的豆包；稳定前缀未利用缓存；摘要/伏笔分两次调用 |
| 质量 | 逐章模式出现两套人名；金额前后不一致；GLM 改写 3 次跑偏；核验步骤输出跑偏成续写 |

## 二、目标

| 维度 | 目标 |
|---|---|
| 操作 | 短故事一篇 **1 步**；长篇一章 **1 步**（一键续写 N 章） |
| 成本 | 短故事 **-60%**；长篇 **-50%**（缓存生效前提） |
| 质量 | 人名/金额一致率 **100%**；AI 特征词不增加；一级违禁词 **0** |
| 可验证 | 每项改动有 A/B 数据，不达标即回滚 |

## 三、方案：五层

### A. 操作层（更易上手）

| 编号 | 改动 | 现状 → 改后 | 收益 |
|---|---|---|---|
| A1 | **一键成书**（短故事） | 建书→骨架→绑模型→成稿→改写→扫描→导出（10+ 次点击）→ **1 次** | 新手可直接用 |
| A2 | **一键续写 N 章**（长篇/中篇） | 每章点 3–5 次 → 选 N 章跑一次 | 连载效率 |
| A3 | 建书表单精简 | 6 项 → **名称 + 一句话设定**（其余默认） | 上手门槛 |
| A4 | 模型两档预设 | 9 个模型逐项绑定 → **省钱档 / 质量档**，高级折叠 | 决策成本 |
| A5 | 首页新手路径 | 7 个 tab → 顶部 3 个入口：**开新书 / 继续写 / 改旧稿** | 导航清晰 |

### B. 流程层（更短）

| 编号 | 改动 | 说明 |
|---|---|---|
| B1 | 短故事 8 步 → **4 步**（设定 → 大纲 → 成稿 → 核验） | 章节级步骤收进后台自动串 |
| B2 | 长篇“开书包” 7 步 → **4 步**（立项 → 大纲 → 黄金三章 → 续写） | 选题/书名/人设合并为“立项” |
| B3 | 条件跳过 | 已有产出且来源未变 → 自动跳过，避免重复花钱 |
| B4 | 核验类步骤禁止写正文 | 提示词硬约束 + 输出形态校验 |

### C. 成本层

| 编号 | 改动 | 做法 | 预估 |
|---|---|---|---|
| C1 | 默认模型 1017 | 首次使用自动设默认；质量档可一键切回豆包 | 起草 -80% |
| C2 | 提示词缓存 | 稳定部分（系统提示/设定/大纲/人设）前置，命中网关缓存 | 输入 -95%（**待验证**） |
| C3 | 摘要 + 伏笔合并 | 1 次调用输出两段 + 校验重试 | 每章省 1 次 |
| C4 | 按需改写 | 本地 AI 词密度低于阈值 → 跳过改写 | 改写 -60~70% |
| C5 | 扫描分级 | 违禁词全程本地免费；逻辑扫描抽样 | 扫描 -80% |
| C6 | 上下文预算 | 6 章 → 4 章（仅省钱档） | 每章 -1~2k token |
| C7 | 用量统计 | 解析 usage，落 gens，看板按书/章/模型统计 | 成本可见 |

### D. 质量层

| 编号 | 改动 | 说明 |
|---|---|---|
| D1 | 人设/金额锁定 | 从设定表提取「人名表 + 关键数字表」，逐章注入 + 生成后校验，不一致拦截 |
| D2 | 伏笔台账结构化 | 埋点章 / 应回收章 / 状态；到期未回收给警告 |
| D3 | 改写兜底 | 被形态/字数保护拦截 → 自动换 1017 重试 1 次 |
| D4 | 大纲偏离检测 | 每 10 章轻量比对，偏离超阈值提示 |
| D5 | 违禁词人工确认 | 一级词允许“确认后通过”，避免误报一刀切 |

### E. 工程层

| 编号 | 改动 |
|---|---|
| E1 | llm.chat 返回 usage（prompt/completion/cache tokens） |
| E2 | 成本看板：按书、按章、按模型、按流程 |
| E3 | 缓存命中率监控 |
| E4 | 每项优化独立开关（配置项），出问题可单独关 |

## 五、风险与红线

### 5.1 三条红线（任何情况下不省）

1. **违禁词扫描**：本地规则，全量跑；
2. **正文形态保护**：防英文分镜/编号列表（实测拦过 3 次）；
3. **人设/金额校验**：防“两套人名”。

### 5.2 各优化的降质风险与兜底

| 优化 | 风险 | 兜底 |
|---|---|---|
| 默认 1017 | 复杂情节细腻度可能不如豆包 Pro | 质量档一键切回；A/B 不达标不设默认 |
| 按需改写 | 检测漏报 → AI 味残留 | 阈值保守；保留“全量改写”按钮 |
| 上下文 6→4 章 | 长线呼应变弱 | 仅省钱档启用；默认 6 章 |
| 合并摘要伏笔 | 单次输出可能敷衍 | 校验字数/条数，不达标重试 |
| 缓存 | 网关若不支持则无效 | 先做缓存命中率监控，无效则回退 |

## 九、结论

- **可行**：10 项里有 8 项技术路径明确、无外部依赖；2 项（缓存、usage）需先验证网关能力。
- **合理**：优先做“零风险高收益”（默认模型、合并调用、一键成书），风险项（缓存、按需改写）先验证再启用。
- **不降质**：三条红线不省；有风险的优化全部配校验与回滚开关。
- **预期**：短故事操作 1 步、费用 -60%；长篇费用 -50%；人名一致率 100%。

## 十、模型方案 v2（2026-10-19 实测后修订）

### 10.1 三模型同题对比（同一份设定 + 大纲，写第 1 章）

| 模型 | 耗时 | 字数 | 中文占比 | 英文行 | 人名覆盖 | 章末钩子 |
|---|---|---|---|---|---|---|
| 豆包 Seed 2.1 Pro | 70.5s | 2,966 | **84.5%** | 0 | 4/4 | 有 |
| **1017** | **15.6s** | 2,966 | 80.3% | 0 | 4/4 | 有（最具体） |
| V4 Pro 0813 | 30.7s | 2,874 | 80.8% | 0 | 4/4 | 有 |

**结论**：V4 Pro（0813）不是"更差"，而是**更慢、且没有质量优势**——速度是 1017 的 2 倍，字数还略少。它不再适合做质量档默认。

### 10.2 修订后的两档

| 用途 | 省钱档 | 质量档 | 依据 |
|---|---|---|---|
| plan（设定/大纲/核查） | 1017 | **1017** | V4 Pro 无优势且慢 |
| draft（起草） | 1017 | **豆包 Seed 2.1 Pro** | 中文占比最高（84.5%） |
| rewrite（改写/钩子） | 1017 | **1017** | GLM 实测 3 次跑偏，1017 稳定且更便宜 |
| summary（摘要/伏笔） | 1017 | 1017 | 两档统一 |
| scan（扫描/核验） | Kimi K2.6 | **Kimi K3** | 强扫描只在质量档 |

两档差异只剩 **draft** 和 **scan** 两处，其余全部统一 1017。

### 10.3 已落地

- 全局默认模型已设为 **1017**（影响新书 + 未绑定步骤；已绑定书不变）。
