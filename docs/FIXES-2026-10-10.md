评审没有发现、我在修复过程中额外查出的 3 个问题：

1. **内部步骤无法重试**：`retry_generation` 只认流程步骤，`summary`/`foreshadow` 这类内部步骤的重试必然失败（"模型/步骤/书缺失"）。
2. **每连接执行 `PRAGMA journal_mode=WAL` 反而制造新错误**：WAL 是数据库级持久属性，每条连接都设需要排它锁，24×30 并发实测有 **4/720** 报 `attempt to write a readonly database`。改为只在建库时设一次后归零。
3. 冒烟测试第 3 步不清理上次失败遗留的同名书 → 清理断言会假失败。

## 二、修复内容

### P0：后台任务必须真后台（核心修复）

`app/flows/runner.py` 新增 `spawn()` —— **有事件循环就挂上去，没有就另起线程跑**，
并**彻底删掉** `except RuntimeError: asyncio.run(...)` 这种静默降级（它正是问题藏身之处）：

```python
def spawn(coro) -> None:
    try:
        loop = asyncio.get_running_loop()
    except RuntimeError:
        loop = None
    if loop is not None and not loop.is_closed():
        loop.create_task(coro)
        return
    threading.Thread(target=lambda: asyncio.run(coro), daemon=True).start()
```

`start_generation` / `retry_generation` / `start_summary` / `start_foreshadows` / `start_finish_chapter`
全部改走 `spawn()`；端点保持同步 `def`（`spawn` 不再依赖调用方上下文，两种写法都安全）。

### P1：WAL + 落库永不抛出

- `store.init_db()` 里一次性 `PRAGMA journal_mode=WAL`（持久属性）；
- `store.conn()` 每次连接设 `busy_timeout=5000` + `synchronous=NORMAL`；
- 新增 `store.update_safe()`：写入失败短暂重试，仍失败只告警不抛；
- `runner._run` / `_llm_once` / `save_web_result` 的所有收尾落库改用 `update_safe`，
  且 `_run` 的落库整段包 try —— 出错也把状态写成 success/failed，**绝不停在 running**（否则该章会被并发锁永久锁死）。

### P2：其余

- `save_web_result`：先查 `chapter_busy()`（有生成在跑就 409 拒绝），并按步骤类型同步 `status`/`progress`；
- `static/app.js`：18 处字面 `\n` 修正为真换行（并保住 `D:\小说导出` 这类真实的路径转义）；
- `safeUrl()`：网页版入口只放行 `http/https`；
- 导出目录白名单：只允许 `data/exports/` 或用户主目录之下，越界返回 400；
- `docs/DESIGN.md`：章节编号重排（八/九/十）、刷掉三处过时描述；
- 冒烟测试：两条假断言改成真断言（防抖用慢模型实测；摘要内容真实断言），并新增「慢模型非阻塞」与「越界导出」两条用例、开头自动清理上次残留；
- 代码质量：`blocks.py` 不再调 `library._sections_of`，改用新公开函数 `library.sections_full()`。
